## 状态规则

- `[ ]`：尚未开始或没有可验证结果。
- `[x]`：该项所属阶段已完成；视觉稿清单中的勾选仅表示该稿已确认，实施清单中的勾选须有资源、代码和对应验证。
- 每一页分别记录：静态检查、微信开发者工具、体验版、真机。前一项通过不代表后一项通过。
- 母版确认只代表设计稿获确认；素材、代码和各验证层级分别标记。全部页面母版确认前，先处理视觉稿与反馈。
- 生成图片只有在进入指定目录、接入运行时、加入打包方案并完成验证后，才能标记为完成。
- 视觉反馈以截图中的实际边界、基线、裁切和层级为准，不能用代码参数推测“应该一致”。

- [ ] 只有在引用数归零、目标构建通过后，才移除对应旧资源和兼容代码。
- [ ] 清理旧 palette、重复绘制函数、失效提示词和过时测试预期；历史资料保留清晰标记。
- [ ] 复核 `images/visual-v1/` 的命名、体积、发布包包含项与参考图排除项。

- [ ] 在文档记录最终验证日期、版本和未覆盖边界。

完成条件：运行时不再出现无意的新旧混搭，旧资源已安全退出，文档状态与实际构建一致。

## 推荐执行顺序

1. 确认模式选择、关卡选择的页面母版及主要状态。
2. 确认排行榜、设置/暂停及所有通用与联机弹窗母版。
3. 确认游戏页、HUD、棋盘、角色和机关的母版；将全部已确认页面并排复核。
4. 冻结共用组件与全项目素材清单，统一制作、拆分并检查素材；首页背景是这一阶段首先制作的素材。
5. 统一接入运行时：共用组件、首页、模式与选关、排行榜与弹窗、游戏页。
6. 完成开发者工具、体验版和真机验收，再清理不再引用的旧资源。

全部页面母版确认是第 4 步的进入条件。任何阶段收到视觉反馈，先修正对应母版或共享组件，再继续后续工作。
