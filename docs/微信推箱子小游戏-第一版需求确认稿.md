# 微信经典推箱子小游戏｜第一版需求确认稿

整理日期：2026-10-10  
状态：产品需求汇总，已开始界面与基础流程实现。以最新对话决定为准。
“已确认”为用户明确决定；“建议”及“待定”不作为已批准需求。

## 1. 项目目标与约束

- 以独立开发副业为方向，第一款选择经典推箱子微信小游戏，侧重轻松解谜、动脑闯关。
- 开发者有网页或软件开发经验，无游戏开发经验。
- 已有个人主体微信小游戏开发者账号。
- 每周可投入 10 小时以上。
- 美术尽量零额外支出，使用现成统一素材。
- 两周内完成首个微信真机试玩版本作为此前确定的阶段目标；增加签到、广告和星级后的具体排期需要重新估算，不承诺两周内完成正式发布。
- 竖屏为既有方向；推箱子完整棋盘及按钮的最终布局尚需原型确认。
- 游戏名称、图标、正式首发关卡数量、开发技术栈未最终确定。

## 2. 核心玩法与操作（已确认）

- 经典规则：角色只能推箱子、不能拉箱子；所有箱子推到目标点后通关。
- 不限时、不限制步数，以思考和解谜为主。
- 使用屏幕十字方向键，每次点击成功移动一格。
- 第一版不支持长按连续移动。
- 推动箱子、角色移动均受墙体和箱子阻挡约束。
- 支持重新开始和消耗撤销卡进行撤销。
- 游玩过程中实时显示当前步数，并记录步数用于通关评星（最新对话已确认按设计稿展示）。

### 计步与撤销口径

- 角色成功移动一格计 1 步，推动箱子同样计 1 步。
- 撞墙或其他无效操作不计步。
- 撤销恢复上一次成功操作之前的角色、箱子位置，并回退该操作对应计步。
- 撤销后继续移动，形成新的有效操作路径，不保留“重做”功能需求。

## 3. 页面与导航

### 3.1 首页（已确认）

- “开始游戏”：直接进入当前最新解锁关卡。
- “关卡选择”：进入选关页。
- “签到”：手动领取每日撤销卡。
- 全部关卡通关后，点击“开始游戏”提示“地图关卡正在开发中”，不自动重玩。
- 仍可通过关卡选择页重玩已解锁关卡。
- 签到未领取的小红点属于此前建议，尚未单独确认。

### 3.2 关卡选择（已确认）

- 关卡依次解锁，完成当前关卡后开放下一关。
- 玩家可以重玩已解锁的关卡。
- 保存每关历史最高星级，重玩表现较差时不降星。
- 建议在关卡格上展示最高星级及锁定状态，具体排版待设计。

### 3.3 游戏主界面（已确认部分）

- 展示棋盘和方向键。
- 撤销按钮直接放在主界面，旁边显示剩余撤销卡数量。
- 重新开始放在游戏菜单内。
- 游戏主界面展示当前步数和历史最佳步数，不展示三星目标步数。
- 当前关卡编号、菜单按钮位置、棋盘自适应方式待视觉原型定稿。

### 3.4 游戏菜单

已确认：
- 重新开始入口位于菜单。
- 点击重新开始直接恢复当前关卡初始布局、清零本局步数和操作历史，不二次确认。
- 已经消耗的撤销卡不返还；未使用的库存保留。
- 音乐、音效分别提供开关，并保存选择。

推荐布局，尚未逐项确认：
- 同一面板放“继续游戏”“重新开始”“返回选关”。
- 底部放音乐、音效开关，不嵌套第二层设置。
- 打开菜单后阻止棋盘和方向键输入，关闭后继续原局面。
- 菜单入口避开平台控件及手机安全区域，最终位置真机确认。

### 3.5 通关面板（已确认）

- 通关后弹出面板，由玩家决定下一步，不自动进入下一关。
- 显示星级、本次步数和历史最佳步数，不展示三星目标步数。
- 普通关卡：显示“下一关”和“再玩一次”。
- 最后一关：将“下一关”替换为“返回首页”，保留“再玩一次”。
- 再玩一次进入同一关初始布局，用于挑战更高星级。

## 4. 星级评分（已确认）

设本关最少通关移动步数为 M，本次有效移动步数为 S：
- 三星：S ≤ ceil(1.5 × M)。
- 两星：ceil(1.5 × M) < S ≤ ceil(2 × M)。
- 一星：S > ceil(2 × M)，只要通关就至少获得一星。
- 门槛向上取整。
- 示例：M=20 时，30 步以内三星，31～40 步两星，41 步及以上一星。
- 每关只保留历史最高星级。
- M 指最少“角色移动步数”，不是最少推箱次数，也不是任意一条解法的长度。
- 尚未求解关卡最优步数。开发时需要验证求解结果并保存评分数据；不能直接将未经证明的解法称为最优解。

## 5. 撤销卡与广告（已确认）

### 5.1 使用规则

- 每撤销一次成功操作，消耗 1 张撤销卡。
- 卡片长期保留，可累积，跨关卡、跨天使用。
- 本局无可撤销操作时，按钮仍可点击，提示“暂无可撤销的操作”。
- 无可撤销操作时不扣卡，也不触发广告弹窗，即使库存为 0。
- 重新开始后清空本局撤销历史，已消耗的卡不返还。
- 卡片累积上限、广告每日次数限制尚未设定，不默认添加限制。

### 5.2 库存不足

- 有可撤销操作但库存为 0 时，点击撤销先弹窗。
- 弹窗文案：“观看广告获得 3 张撤销卡”。
- 玩家明确点击观看后，才播放激励视频广告；可以取消。
- 完整观看后只增加 3 张卡，不自动撤销。
- 玩家再次点击撤销，才扣除 1 张卡并执行撤销。

### 5.3 广告结果

- 完整观看：发放 3 张撤销卡。
- 主动中途关闭：不发卡。
- 已联网但广告加载失败：免费发放 3 张撤销卡。
- 未联网：提示“请联网后再试”，不发卡。
- “加载失败补偿”延续此前每次失败补偿的方向；展示阶段失败、网络状态无法确定等边界需实施前确认。
- 只在用户明确发起的领取流程内发奖，后台预加载失败不应自行发奖。
- 技术验收建议：一次领取流程最多发奖一次，避免重复回调、连续点击造成重复发卡。
- 推箱子其他广告位没有确认；不沿用旧寻物方案的续时广告，不擅自添加启动、通关或重开广告。
- 个人主体账号是否已开通激励广告、是否具备接入条件、正式广告位 ID 尚待核实。

## 6. 每日签到（已确认）

- 首页设签到入口。
- 玩家手动点击领取，每天限领一次。
- 每次发放 5 张撤销卡。
- 按北京时间（UTC+8）每天凌晨 0 点刷新。
- 库存累积保留，不因次日刷新而清零。
- 不因单纯打开游戏自动领取。
- 未确认额外新手赠卡，不能默认增加首次登录奖励。
- 离线能否签到、设备时间回拨如何处理尚待确认；本机存档无法天然保证可靠的服务器时间校验。

## 7. 存档（已确认）

第一版仅本机保存：
- 已解锁关卡和通关状态。
- 每关历史最高星级及历史最佳步数。
- 撤销卡库存。
- 最后一次签到的北京时间日期。
- 音乐、音效开关选择。
- 新手引导完成或跳过标记。

不保存：
- 未完成关卡中的角色、箱子位置。
- 未完成关卡的当前步数和撤销历史。

退出关卡或游戏后再次进入，恢复关卡初始布局。打开菜单再关闭属于继续当前局面，不视为重新进入关卡。

限制：
- 无云端同步；换设备或清除本地数据可能导致进度、库存等无法恢复。
- 第一版不加入账号云存档、后端库存校验；如后续引入，另行设计。

## 12. 第一版开发顺序（建议）

1. 跑通微信开发者工具和手机预览，显示一张地图及 Kenney 素材。
2. 实现移动、碰撞、推箱、通关和重新开始。
3. 实现首页、选关、依次解锁、通关面板和本机存档。
4. 接入内部计步、经验证的评分门槛、最高星级记录。
5. 实现撤销历史、卡片库存、签到、激励广告和异常处理。
6. 添加操作引导、跳过入口、声音开关及基本动画。
7. 在不同手机上验证操作、屏幕适配、切后台恢复和存档。
8. 完成地图许可和平台发布条件核对，再进入正式提审。

建议先用测试奖励模拟验证发卡和扣卡，再接真实广告；没有真实广告验证时不能将模拟通过描述为广告上线成功。

## 13. 核心验收清单

- 墙体不可穿越，一次只能推动一个箱子，箱子不能被拉动。
- 无效操作不移动、不计步、不进入撤销历史。
- 所有箱子归位后只结算一次，正确解锁下一关。
- 当前步数、通关步数和历史最佳步数显示正确，撤销时步数同步回退，评分在门槛边界上符合规则。
- 重玩较差不覆盖最高星级。
- 撤销同时恢复位置和计步，且只扣一张卡。
- 无历史时提示正确，不扣卡、不弹广告。
- 广告确认、完整观看、提前关闭、加载失败、无网络分别走对应分支，一次请求不重复发卡。
- 签到每天北京时间限领一次，库存跨关跨天保留。
- 重开清空局面历史和计步，不返还已用卡。
- 退出后不恢复未完成局面，但保留解锁、星级、库存与签到记录。
- 全部通关后首页提示正确，最后一关按钮正确。
- 引导可操作、可跳过，完成后不重复自动出现。
- 声音开关独立生效，选择可保存。

## 14. 历史方案与替代关系

最初讨论过自然场景寻物、黑白图标找物、限时加秒、广告续时等方向，现已改为经典推箱子。

以下旧方案不纳入当前第一版：
- 小花园等 5 个生活场景及寻物目标栏。
- 找齐指定物品、随机出现数量、画面拖动与捏合缩放。
- 60 秒倒计时、找对加 5 秒、广告续时 30 秒。
- 圈出物品位置的提示功能。
- 找物版本的广告补偿内容；当前对应奖励已改为 3 张撤销卡。

推箱子中较早的“不支持撤销”也已被新规则覆盖：现在支持消耗撤销卡撤销。
