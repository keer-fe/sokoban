# 在线双人房间模块

## 目标

双人 PK 是受邀玩家通过房间码在两台设备进入同一房间并比赛，不是本地轮流操作。

双人合作复用同一套房间生命周期。双方操作同一个棋盘，每个方向操作通过云函数事务串行写入共享操作序列；两端按同一序列重放，任一端完成关卡后房间共同结算。

## 组成

- `src/platform/pk-rooms.js`：客户端创建、加入、同步、合作移动和结算接口。
- `src/game/controller.js`：房间状态进入游戏流程。
- `cloudfunctions/managePkRoom/`：房间创建、加入、进度和结束处理。
- `pk_rooms`：CloudBase 房间集合。

房间身份以微信 OPENID 为准，客户端不能自行声明胜负或替代另一名玩家。

## 生命周期

1. 房主创建房间并获得房间码。
2. 第二台设备输入房间码加入。
3. 双方进入同一关卡并同步开始状态。
4. PK 客户端提交比赛成绩，服务端判断胜负；合作客户端逐步同步共享操作，完成后共同结算。
5. 离开、超时或异常状态需要得到明确处理。

## 验证边界

自动化测试和云函数处于 Active 只能证明代码路径与部署状态。完整的“创建 → 第二台设备加入 → 双方完成 → 返回胜负”以及 `pk_rooms` 首次写入权限，仍需要真实两设备验证后才能声明上线完成。

合作模式同样必须在两台设备验证“创建 → 分享进入 → 双方准备 → 交替操作 → 同步完成”，尤其检查弱网下的操作延迟和前后台恢复。
